Architecture Overview

  • Next.js App Router — File-based routing with layouts, loading states, and error boundaries
  • Server Components — Data fetching happens on the server by default for performance
  • Server Actions — Form submissions and mutations use Server Actions for type-safe RPC
  • API Routes — REST endpoints in src/app/api/ for programmatic access

Provider System

The provider system uses a ProviderManager that handles automatic failover between configured providers.

Provider Interfaces

  • AIProvider — Text generation, product parsing, chat (OpenRouter, OpenAI)
  • SearchProvider — Product search and identification (SerpAPI)
  • PriceProvider — Price tracking and history (Keepa)

Failover Logic

  1. Providers are sorted by priority (lower number = higher priority)
  2. Requests go to the highest-priority enabled provider
  3. On failure, the next provider in priority order is tried
  4. All provider API keys are encrypted at rest using AES-256

Authentication

  • Session-based — No JWTs; sessions are stored in the database
  • Token hashing — Session tokens are SHA-256 hashed before storage
  • Sliding window renewal — Sessions are extended on activity
  • Roles: OWNER (full control), ADMIN (manage users), USER (standard access)

Database

  • ORM — Prisma with type-safe client generation
  • Database — PostgreSQL 15+
  • Migrations — SQL migrations in prisma/migrations/, managed via prisma migrate
  • Schema — See Database Schema

Upload System

  • Files are stored on local disk at the path specified by UPLOAD_DIR
  • Upload endpoint: POST /api/upload (multipart/form-data)
  • Files are renamed with unique identifiers to prevent collisions
  • Media records track original name, MIME type, size, and uploader

Contributing

  1. Fork the repository on GitHub
  2. Create a branch from main for your feature or fix
  3. Write code following the existing patterns and conventions
  4. Commit using conventional commit messages (enforced by commitlint)
  5. Push and open a Pull Request

Code Quality

  • lint-staged runs on every commit via Husky git hooks
  • ESLint for code quality and error detection
  • Prettier for consistent formatting
  • commitlint enforces conventional commit message format

Branch Naming

feature/short-description
fix/issue-number-description
docs/what-changed

Commit Message Format

type(scope): description

# Examples:
feat(wishlists): add copy wishlist endpoint
fix(auth): handle expired session renewal
docs(api): document provider endpoints
